## 1. Current architecture — the headline finding

> **There is no question artifact.** The entire flow is Dart source in
> `wellapath-mobile`.

| Concern | Where it actually lives |
|---|---|
| Follow-up question content | `lib/core/constants/followup_question_map.dart` — 18 token keys, 40 authored questions |
| Red-flag clarifiers | `lib/core/constants/red_flag_clarifiers.dart` — 3 clarifiers |
| Selection, ordering, truncation | `lib/features/assessment/question_engine.dart` — a static class |
| Answer → token mapping | `lib/features/assessment/followup_screen.dart` |
| Demographic questions | five separate Flutter screens with hardcoded navigation |
| Assessment state | `lib/features/assessment/assessment_controller.dart` (in-memory) |
| Picker vocabulary | `lib/core/constants/symptom_display_map.dart` — 123 labels → 121 tokens |

Consequences, stated plainly:

- no artifact version, no hash in any manifest, **no `/config` entry**;
- a question change ships **only as an app release**;
- it **cannot be rolled back** the way `kb`, `rules` or `token_dictionary` can;
- questions are always available offline because they are compiled into the
  binary — the same property that makes them un-updatable.

The six source files are vendored into `baseline/questions_v1/` and hashed, so
this baseline is pinned to real bytes rather than to a transcription.

## 4. Condition language

`tools/qflow/conditions.py`. Closed, declarative, finite, offline, deterministic.

**13 operators, and no others:** `all`, `any`, `not`, `equals`, `one_of`,
`token_present`, `token_absent`, `prior_answer_equals`, `age_range`, `sex`,
`pregnancy`, `always`, `never`.
**4 readable fields:** `sex`, `age_token`, `body_area`, `assessment_phase`.

Explicitly absent: expression parsing, scripting, regular expressions over
clinical free text, network access, probabilistic/fuzzy/AI branching. A test
asserts no operator name contains `regex`, `matches`, `contains`, `like`,
`similarity` or `score`.

**Fail-closed rules**, each tested:

- unknown operator, unknown field, or more than one operator key → **error**, not `false`;
- a condition naming a token that does not exist → **validation failure**;
- unknown `sex`, unknown `pregnancy`, unknown age → the condition is **false**.
  An unanswered question is not the same as "no", so an age-gated question is
  *not asked* rather than wrongly asked;
- `{"all": []}` is **true**, `{"any": []}` is **false** — stated so two
  implementations cannot silently disagree.

## 5. Ordering and branching

Order key: **`(priority, tie_break_key, question_id)`**. Never map iteration,
file order, or an unstable sort.

- Every question declares a `tie_break_key`. A priority tie with no declared
  resolution is a **validation failure**.
- Order keys must be unique — enforced.
- A test sorts the question list forwards and reversed and requires the same
  result.

Priority bands: red-flag clarifiers `0` → severity `10` → duration `20` →
additional symptoms `30` → demographics `100+`. This reproduces the current
emission order, with clarifiers first.

**Already-answered** questions are not re-presented. **Newly eligible** questions
join at their declared position. **Newly ineligible** questions are withdrawn and
their derived tokens removed. **Cycles** and **repeated questions** are
`required` controls in `path_controls`; the branch graph is cycle-checked.

## 6. Red-flag precedence

The contract requires evaluation:

1. after **every** answer whose question can affect a red flag;
2. after an **edited** answer;
3. after **restored** state;
4. **before** selecting or presenting the next ordinary question;
5. **before** scoring;
6. **before** ordinary results rendering.

Every red-flag-affecting question declares
`evaluate_after_answer: true` and `blocks_next_question: true`; a validator
fails if any does not, and a second validator fails if the declared hook
disagrees with the computed effect (`red_flag_effect_and_hook_agree`).

**When a red flag becomes active:** branching stops immediately, scoring cannot
override it, emergency presentation wins, and queued unrelated questions are not
shown first. Verified across 2,325 explored paths — no red-flag question ever
queues behind an ordinary one, and none is ever dropped by truncation.

### Editing away a red flag

If an edit removes the answer that raised a red flag, the red flag is
recomputed from current state and may clear. But **advice already shown cannot
be unshown.** The contract therefore requires that the assessment record retains
that an emergency was presented, and that clearing it is presented as a
*correction the user made*, never as a silent downgrade. This is a stated
requirement for Mobile, not something this repository implements.

## 7. Answer editing and invalidation

Dependency-based, never "keep everything and hope".

1. The user selects a previous question by its **stable ID**.
2. Its `invalidates_on_change` list identifies dependents.
3. Dependent answers are **cleared** — back to unanswered, not to a default.
4. Tokens derived from cleared answers are **removed** from the token set.
5. Eligibility is recomputed from the resulting state.
6. Preserved answers are those whose questions are still eligible and not
   downstream of the edit.
7. Red flags are re-evaluated **before** the next question is presented.
8. Scoring is recomputed only after red-flag evaluation completes.

**Convergence:** invalidation is a walk over a DAG — `no_question_invalidates_itself`
and `no_branch_cycles` are enforced — so it terminates. A test re-runs
recomputation five times and requires an identical result.

Already implemented today, and projected: `setSex` clears `pregnancy` when sex
is not female. That is the model, generalised.

## 8. Skip semantics

Six distinct states, kept apart:

| State | Stored as |
|---|---|
| Not applicable | **No answer state at all** — the trigger is false |
| Optional, explicitly skipped | A **skip sentinel** answer option, distinct from any value |
| Required, unanswered | Unanswered; the flow **cannot advance past it** |
| Invalidated by editing | Cleared back to unanswered |
| Assessment abandoned | Terminal; no result |
| Interrupted by a red flag | Terminal; emergency presentation |

- A skip sentinel **must produce no clinical token** — enforced.
- A required question **cannot be skippable** — enforced.
- The projection introduces **no skips**: every question is `skippable: false`.
  The capability exists; using it is a separate reviewed decision.

3 (×161), 4 (×340), 5 (×1,792). Max 5, min 1.

**Truncation rule:** drop lowest-priority questions until the count fits — but a
red-flag-affecting question is **never** dropped. If red-flag questions alone
exceed the limit, **the limit yields**, not the safety question.

(`keep_5`, `raise_to_7`, `red_flag_exempt_only`) and
`final_threshold_status` reads **PENDING product and clinical approval**. A test
asserts it still says PENDING.

## 10. Privacy

On-device state may hold the clinical answers the assessment needs. **None of it
may leave the device.**

Prohibited from Backend and telemetry: question IDs correlated with a session,
answers, selected symptoms, derived tokens, red-flag IDs, rule IDs, scores,
urgency, narrative clinical text, and complete or partial paths.

**Telemetry contract v1.0 is unchanged.** The existing session already records
only an opaque ID and three counters, and `followup_screen.dart` deliberately
records a step view with **no** `step_count`, because the count is derived from
the symptom set and would leak it. That property must be preserved.

Permitted local measurement, aggregate and non-clinical only: path length
distribution, question count, time-to-complete, all computed in tests, never
transmitted.

The candidate contains **no free-text answer type** — every answer is an
enumerated option ID. A PHI scan over the whole artifact runs in CI.

## 11. Lifecycle, activation and rollback

**Not published. Not active. Not consumed by any build.** `may_publish: false`,
no clinical review recorded, no `/config` entry, nothing uploaded.

**Activation prerequisites** — all outstanding:

1. Product approval of question wording (`content_approved` is `false` on all 50).
2. Clinical approval of IM-002 (immediate red-flag evaluation).
3. Product + clinical approval of a final path-length threshold.
4. Engineering-lead approval of the artifact.
5. Mobile implementation of the contract behind a flag.
6. A distribution decision: **the flow is compiled into the app today.** Serving
   it as an artifact means a new `/config` entry, a download path and a
   last-known-good fallback — none of which exists. Until then a "published"
   question artifact would have no consumer.

**Rollback:** nothing to roll back — no behaviour changed. Reverting this PR
removes documentation, reports, fixtures and an unused candidate. Once the flow
*is* served as an artifact, rollback follows `docs/VOCABULARY_ROLLBACK.md`:
revert the `/config` block; never delete a published version.

## 12. Known limitations

- **Not exhaustive over the full state space.** The follow-up graph is driven by
  the symptom token set, whose powerset is not enumerable. Exploration is
  exhaustive over every subset of the 24 trigger tokens **up to size 3** —
  2,325 combinations. Larger subsets can only *add* eligible questions, and
  truncation plus the red-flag exemption are verified on every explored subset,
  so the bound is a coverage limit rather than a soundness gap. It is declared
  in `exploration.uncovered_state_space`, not glossed.
- **No running-app equivalence proof.** This repository holds no Flutter runtime
  and must not grow a second engine. Executable proof belongs in the mobile
  repository once the contract is implemented.
- **The Dart parser is not a Dart parser.** It recognises the specific literal
  forms these six files use and **raises** on anything else, so a future edit it
  cannot read fails loudly instead of silently shrinking the baseline.

## 13. Required clinical / product decisions

1. **IM-002 — immediate red-flag evaluation.** Clinically safe direction
   (earlier, never later), but a real behaviour change. **Engineering lead + clinical.**
2. **Question wording approval.** All 50 are `content_approved: false`; the text
   is carried verbatim for traceability, not blessed. **Product + clinical.**
3. **Final path-length threshold.** Three options proposed, none approved. **Product.**
4. **Whether any question may become skippable.** None is today. **Product + clinical.**
5. **QB-009 — the `0–12` age band maps to `children_under_5`,** so a 6-to-12-year-old

6. **QB-005 wording collisions.** IM-001 picks deterministically by token ID; a
   reviewer should confirm the chosen wording is the right one. **Product.**
7. **Distribution model** — compiled-in versus served artifact. **Engineering lead.**
