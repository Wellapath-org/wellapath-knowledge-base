# facilities.ng.v1.2 — release and rollback

**Status: candidate. Not approved, not published, not served.** No manifest
points at it and no build consumes it.

## What it is

v1.1's facility records with the 45 NHFR-derived telephone numbers removed,
and a corrected licence block. Generated by `tools/build_facilities_v1_2.py`
from `facilities.ng.v1.0.json`, which is the last version before the
enrichment.

**No record was added, removed, moved or renamed.** Identities, coordinates,
types and states are byte-identical to both v1.0 and v1.1.

## Why

v1.1 carried 45 telephone numbers imported directly from a Nigeria Health
Facility Registry export. NHFR publishes no licence and no terms of use, and
its only public rights statement reserves all rights, so written
redistribution permission for those values was never captured.

**This is not a privacy remediation.** No personal-data breach was
established: the removed values name no individual, and the source export's
officer-contact columns are empty on every row. The classification is a
public-source facility-data licensing and attribution gap.

user-facing string.

## Release steps

Not to be performed until the candidate is independently reviewed and
approved.

1. Merge this branch. v1.2 lands alongside v1.1; nothing is served yet.
2. Publish v1.2 and its checksum to the artifact host.
3. Update the manifest and current-version pointer from 1.1 to 1.2.
4. Confirm a client fetches 1.2 and its checksum verifies.
5. Forward-remove `facilities.ng.v1.1.json` from the public branch in a
   separate commit, keeping this record of why.

## Rollback

Each step reverses independently, and the data is identical apart from 45
null-versus-populated phone fields, so rollback carries no data risk.

| If | Then |
|---|---|
| A client fails to parse 1.2 | Point the manifest back at 1.1. It is unchanged on the host until step 5. |
| Step 5 has already run | Restore `facilities.ng.v1.1.json` by forward commit from `git show <commit>:facilities.ng.v1.1.json`. **No history rewrite.** |
| The checksum mismatches | Do not repoint. Re-run `--check`; a mismatch means the file was hand-edited. |
| A rollback to 1.1 is needed for longer than a few hours | Record it. Serving 1.1 re-exposes the 45 unlicensed values, which is the condition this artifact exists to end. |

Rolling back to **1.0** is also safe and carries no licensing exposure: its
records are identical to 1.2's and it has no NHFR values. It lacks the licence
block, so 1.2 is preferred.

## Not resolved by this artifact

* The 45 values remain in the shipped v1.1 until step 5, and in Git history
  permanently. **No history rewrite is planned or required** — the
  classification is licensing, not breach.
* The database remains a **Derivative Database** under ODbL because 896 of
  its 5,344 records are OSM-derived. v1.2 declares this; it does not change
  it. The GRID3-only candidate in PR #42 would remove the ODbL obligation
  entirely and is the strategic destination.
